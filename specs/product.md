# OmniPost 产品规格

服务中小企业：用内容做自媒体、管达人、**获客**。获客是主业，不是短链插件。
企业主不坐在电脑前，必须能在手机上随时处理审批、线索和失败。

获客只走「有用的本地内容 → 平台允许的钩子 → 线索箱 → 企业主手机跟进」。
不靠买量、不靠刷量、不靠违规导流。账号权重是合规原创和本地真实内容的结果，不是承诺，也不是单独产品。

## 谁在用

| 角色 | 场景 | 主设备 |
|---|---|---|
| 企业主 | 出门、开会、下班后：看今日有没有发出去、审批稿、回一条线索、催达人 | 手机（随时随地） |
| 运营 / 代运营 | 写稿、改各平台文案、排窗口、维护企业档案、绑定账号、跟达人档期 | 手机 + 电脑 |
| 平台管理员（我们） | 开企业、管权限、看出错日志 | 电脑；后台本机 Docker 即可 |

## 三端，同一套业务

1. **企业主 App（必须）**：React Native（Expo）。审批、今日队列、线索待办、达人跟进、失败 / 待审批 / 新线索 / 合规拦截推送。离线能看已缓存的待办，联网再提交。
2. **运营工作台**：现有 Next.js，先做成手机也能用的 PWA（可加到主屏幕）。电脑上做重活（改六平台文案、企业档案、日历、账号授权）。
3. **管理后台 `/admin`**：多租户、员工、审计。本机 `docker compose` 跑起来即可，不要求做成手机 App。

不要做 Electron。企业主不会为了发微博或回线索去装桌面客户端。

## 模块（按企业租户隔离）

- **企业档案 / 本地生活**：城市、商圈、业态、营业时间、地标、方言分寸、节令。写稿和排期要读这份档案。
- **自媒体**：写一篇 → 按平台规则改写成六套 → 按平台窗口排期 → 队列与失败重试。默认模拟发布。
- **获客（核心）**：活动、平台允许的 CTA、公开短链、线索箱、跟进状态。企业主在手机上处理。
- **达人**：档案、报价、合作档期、交付链接、结算状态。
- **后台**：企业（租户）、角色（超管 / 企业管理员 / 运营 / 只读）、审计。

六平台：微博、微信公众号、小红书、X、Facebook、Instagram。凭证按租户存，不写进仓库。

## 企业档案与本地生活

每个租户一份经营档案。系统用它改编文案和建议发布时间，不拿它做广告定向或地图产品。

**要有的字段（本期就这些）**

- 城市、行政区、商圈或街道
- 业态（餐饮 / 零售 / 到店服务 / 其他本地生活）
- 品类或菜系（如川菜、咖啡、儿童摄影）
- 店名、可对外说的地址或路口
- 营业时间、固定休息日
- 附近地标（2～5 个，供正文点到为止）
- 方言分寸：默认书面普通话；可选「略带口头禅」，禁止整篇方言或生造口音
- 节令与社区节奏：周末、节假日、开学、旅游季、店庆——只作提示，不自动生成营销日历产品
- 受众时区：国内账号默认 `Asia/Shanghai`；X / Facebook / Instagram 若主要服务海外，用工台填写的受众时区，未填则警告「仍按上海窗口，海外账号可能发空」

**做什么**

- 写稿改编必须带入可核对的本地事实：城市场景、品类、营业时段、地标。禁止写成全国通用鸡汤再硬贴城市名。
- 餐饮等到店业态，排期要避开「店关着、受众不在」的空窗；可偏向用餐前 / 下班后 / 周末出门前。
- 企业主在 App 里最多改一句当日状态（今日店休、今晚延长营业、本周有节令）。运营在工作台维护完整档案。

**不做什么**

- 不做 LBS 广告、附近推送、电子围栏、竞品铺位监控。
- 不要求企业主在手机上填完整档案。
- 不把方言、节令做成自动段子机。

## 平台合规

发布前按平台拦截，不把违规稿送进队列。模拟发布也要跑同一套检查，避免「演练过了、真发被罚」。

**六平台都要**

- 原创：一稿六发必须改编，禁止同一正文原样贴到所有平台。转载须标明；不能标原创的不要勾「原创」。
- 禁垃圾：禁止同一账号短时间连发高度重复稿、标题党堆砌、标签堆砌、诱导「必赞必藏必关」。
- 禁虚假互动：不自动点赞、评论、关注、转发、刷播放。
- 禁违禁承诺：不写医疗疗效、金融保本、虚假稀缺、绝对化国家认证（具体词库可后续补，本期先做人能看懂的硬警告）。
- 禁把评论区当群发器：可以邀请读者评论关键词，**系统不代发评论、不代回评论、不代私信**。资料由企业主或运营人工发。

**分平台 CTA（现行逻辑必须改到这里）**

| 平台 | 允许的获客钩子 | 禁止 |
|---|---|---|
| 微博 | 邀请评论关键词；资料由人工回复。外链可用但不要刷。 | 批量重复、诱导转发关注、自动评论。 |
| 公众号 | 正文或菜单放短链；可写加微信。以打开 `/go/{slug}` 留资为主。 | 诱导分享裂变、夸张赠品欺诈。不代替微信私信客服。 |
| 小红书 | 先把笔记写完整。钩子只用「评论关键词，人工发资料」。封面必有。 | **正文、标题、评论引导里不得出现微信号、二维码、站外短链、导流话术。** 当前「加微信 xxx」必须停用。 |
| X | 文案 + 短链。 | 自动回复、重复垃圾推文。 |
| Facebook | 文案 + 短链或落地页。本地店可带地点，不做广告后台。 | 买量、假互动。 |
| Instagram | 图必有。钩子用 link in bio / 简介短链；可写「主页链接」。 | **caption 不当可点外链用。** 不自动 DM。可写「私信关键词」，但系统不代回。 |

拦截发生在：工作台写稿预览、送审、入队之前。企业主审批页必须看见原因，并能「改一句 / 驳回」，不能只有桌面长报告。

## 算法与账号权重

目标：少触平台惩罚、多给真实本地内容被分发的机会。**不承诺上热门、起号、涨粉。**

**做什么**

- 窗口按平台，不共用一个「中国高峰」打发海外账号。
  - 国内（微博 / 公众号 / 小红书）：保留早通勤、午间、下班、晚间刷机；再叠加档案里的营业与用餐节奏。
  - 海外（X / Facebook / Instagram）：用受众时区的常用窗口；未填时区要警告。
- 多平台错开，避开整点扎堆。同一账号当日不连发近义重复稿。
- 遵守各平台字数硬限、小红书 / Instagram 必须有图、公众号可有摘要。
- 正文前段先给信息（是谁、在哪、解决什么），钩子放后；小红书尤其禁止开头导流。
- 稳定垂类：标签来自档案品类和本稿，不堆无关热词。
- 企业主今日页只显示「下一档时间 + 平台」，不出现复杂网格。

**不做什么**

- 不买热搜、不买推荐、不做广告计划 / 出价 / 素材投放。
- 不做权重分数、健康度仪表盘、对标账号监控。
- 不复制爆款整篇、不伪装真人互暖。
- 不把「跟算法」做成必须坐在日历前才能获客。

## 获客边界

获客 = 本地有用内容带来自然进线，再落到平台允许的钩子和线索箱。

**做什么**

- 活动：名称、目标、赠品 / 资料、关键词、微信号、短链 `/go/{slug}`。
- 写稿挂活动后，按上表生成 CTA，不合规的平台不生成该钩子。
- 未登录访客能打开短链并留资；线索进该租户箱子。
- 企业主手机：待跟进列表、改状态（新 / 已联系 / 成交 / 流失）、复制微信。30 秒内处理一条。
- 新线索、发布失败、合规拦截要推到企业主手机。

**不做什么**

- 不做广告投放与买量。
- 不代替微信 / 小红书私信客服，不自动回评发资料。
- 不自动关注、不刷评、不互赞。
- 不把获客做成桌面投放中台。没有运营时，企业主仍能在手机回线索、批稿。

## 非目标（本期不做）

- 达人自己用的投稿 App
- 广告投放与买量（含热搜、粉赞播放、信息流计划）
- 代替微信 / 小红书私信客服
- 自动评论 / 自动私信 / 假互动
- 权重评分、起号保证、竞品监控
- Electron 或 Flutter 客户端

## 验收

### 企业主 30 秒跟线索

- Given 该租户线索箱有一条新线索，且企业主手机已登录
- When 他打开待办或点推送
- Then 他能在约 30 秒内看到来源、改状态、复制微信；全程不需要电脑

### 审批看见合规原因

- Given 一篇小红书稿正文含微信号或站外短链
- When 运营送审或入队
- Then 系统拦截，不进入可真发队列；企业主审批页用一句话说清原因，可驳回或让运营改；模拟发布也必须同样拦截

### 获客钩子分平台

- Given 活动同时挂微博、公众号、小红书、Instagram
- When 生成各平台文案
- Then 微博可出现评论关键词；公众号可出现短链和微信；小红书只有评论关键词、无微信无短链；Instagram 只指向主页链接 / bio，caption 不当外链按钮

### 本地生活进正文和排期

- Given 档案为「成都 / 春熙路 / 川菜 / 11:00–21:30」
- When 运营写一篇到店相关稿并选「下一档」
- Then 改编后的正文能核对到城市或商圈或品类或营业信息之一，且建议时间落在该店营业相关窗口，而不是全国空泛鸡汤 + 固定空窗

### 海外窗口不用上海硬套

- Given 租户为 Instagram 填了受众时区（非上海）
- When 系统建议 Instagram 发布时间
- Then 使用该时区窗口；若未填，仍可排期但必须出现警告，不能静默按北京高峰发出

### 禁止刷量与买量入口

- Given 任何角色打开三端
- When 寻找投放、买热门、自动评论、自动私信
- Then 没有这些入口；队列只发人工确认过的原稿改编，不代操作互动

### 桌面不是获客前提

- Given 企业主当天只有手机
- When 他要批一篇、回一条线索、看失败
- Then 都能在 App 完成；企业档案全文编辑、OAuth、六平台并排改稿可以只在工作台，但不阻塞上述三件事
